# 08_DESIGN_CONSTRAINTS.md

# Design Constraints

Version 1.0

---

# Purpose

Constraints create identity.

Unlimited freedom almost always produces generic work.

This document defines the boundaries within which the portfolio should be designed.

Every future decision should be evaluated against these constraints.

---

# Principle

The portfolio should feel inevitable.

Not experimental.

Every visual decision should feel as though it could not have been made differently.

---

# Identity Constraints

Always communicate

Product Engineering

Systems Thinking

Craftsmanship

Curiosity

Trust

Never communicate

AI Influencer

Frontend Wizard

Animation Showcase

Award Chasing

Technology Evangelism

---

# Story Constraints

The creator is always the protagonist.

Projects support the creator.

Technology supports the projects.

Animation supports technology.

Nothing should reverse this hierarchy.

---

# Information Constraints

Visitors should never encounter large paragraphs.

Maximum idea density.

One major idea per screen.

One primary interaction per moment.

One visual focus per section.

Information should be progressively disclosed.

Never overwhelm.

---

# Layout Constraints

No traditional landing page.

No hero full of buttons.

No "About Me" immediately.

No skill bars.

No percentage indicators.

No timeline on the homepage.

No technology cloud.

Whitespace is mandatory.

Every section must breathe.

---

# Motion Constraints

Motion should explain.

Never decorate.

Every animation must satisfy one of these:

Guide attention.

Reveal hierarchy.

Connect ideas.

Communicate state.

Explain engineering.

If it satisfies none,

remove it.

---

# Scroll Constraints

Scrolling should feel cinematic.

Never abrupt.

Never infinite.

Every scroll should produce a meaningful change.

Scrolling should never simply move content upward.

It should move the visitor through an experience.

---

# 3D Constraints

Three.js exists to improve understanding.

Never use 3D because it looks impressive.

Only introduce dimensionality when it explains

products

systems

engineering

ideas

If replacing a 3D object with a static image loses nothing,

remove the 3D object.

---

# Performance Constraints

Desktop

Target 60 FPS.

Tablet

Maintain smooth interaction.

Mobile

Prioritize readability.

Lazy load everything heavy.

Progressively load worlds.

Unload inactive scenes.

Reduce GPU pressure.

Prefer quality over quantity.

---

# Accessibility Constraints

Keyboard navigation.

Reduced motion support.

Readable contrast.

Meaningful focus states.

Semantic HTML.

Screen reader friendly.

Animations must never become required to understand information.

---

# Typography Constraints

Maximum two typefaces.

Clear hierarchy.

Large headings.

Comfortable reading widths.

Avoid decorative typography.

Typography should feel editorial.

Not futuristic.

---

# Colour Constraints

Never rely on colour alone.

Every world receives its own atmosphere.

Atmosphere is created through

lighting

materials

contrast

spacing

motion

Colour supports.

Never dominates.

---

# Glass Constraints

Glass should appear premium.

Not trendy.

Navigation.

Expandable panels.

Floating cards.

Never entire pages.

---

# Interaction Constraints

Every interaction should answer

"What happens if I explore?"

The visitor should always be rewarded.

Never punish curiosity.

---

# Screenshot Constraints

Only real screenshots.

Never fabricate UI.

Never create fake dashboards.

Never invent metrics.

If an asset doesn't exist,

leave a placeholder.

---

# Photography Constraints

Portrait should appear once.

Near the end.

Never dominate the homepage.

The work introduces the person.

The portrait confirms the person.

---

# Technical Constraints

Use real project assets.

Use repository diagrams where appropriate.

Represent architecture truthfully.

Do not simplify engineering until it becomes inaccurate.

---

# Emotional Constraints

The experience should feel

Calm.

Confident.

Thoughtful.

Never

Chaotic.

Overstimulating.

Aggressive.

Overly futuristic.

---

# Decision Rule

If two designs are equally attractive,

choose the one that

explains more,

requires less,

lasts longer.
