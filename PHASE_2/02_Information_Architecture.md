# Phase-2-Experience/02_INFORMATION_ARCHITECTURE.md

# Information Architecture

Version 1.0

---

# Purpose

Information architecture determines

when

information appears.

Not merely

where.

The portfolio should reveal knowledge in layers.

Never dump information.

---

# Core Principle

Curiosity first.

Explanation second.

Details third.

Implementation last.

---

# Information Pyramid

Identity

↓

Purpose

↓

Problem

↓

Solution

↓

Product

↓

Engineering

↓

Implementation

↓

Repository

Every project follows this hierarchy.

No exceptions.

---

# Homepage

Should answer

Who?

Never

How?

---

# Creator Section

Should answer

Why?

Never

Everything.

---

# Project Landing

Should answer

What?

Never

Architecture.

---

# Expanded Project

Should answer

Why?

How?

Outcome.

Only after intentional interaction.

---

# Deep Dive

Architecture.

Database.

Infrastructure.

Code.

Stack.

Diagrams.

Only visitors actively exploring should reach this layer.

---

# Information Density

Every screen

One primary message.

Maximum two supporting ideas.

No competing hierarchy.

Whitespace is information.

---

# Reading Behaviour

Assume

Recruiters scan.

Founders explore.

Engineers investigate.

Designers observe.

Design accordingly.

---

# Progressive Disclosure

Every project

Level One

Recognition

↓

Level Two

Problem

↓

Level Three

Thinking

↓

Level Four

Engineering

↓

Level Five

Implementation

↓

Repository

Every click should increase understanding.

Not complexity.

---

# Navigation Information

Navigation should communicate

Location.

Progress.

Remaining journey.

Nothing else.

Navigation is not content.

---

# Technology Placement

Technology should never appear before

Problem.

Users care about

why.

Not

React.

Three.js.

Supabase.

GSAP.

Technology should feel discovered.

Never announced.

---

# Visual Assets

Visuals should communicate before text.

Screenshot.

↓

Animation.

↓

Diagram.

↓

Paragraph.

↓

Repository.

This order should remain consistent.

---

# Text Philosophy

Visitors should never read long paragraphs.

Replace explanation with

interaction,

animation,

diagrams,

motion,

visual hierarchy.

Text exists only when visual communication becomes insufficient.

---

# Engineering Information

Engineering should answer

Why was this designed this way?

Not

Look how complicated this is.

Avoid technical ego.

Explain decisions.

Not difficulty.

---

# Final Layer

The repository is the final layer.

Only highly curious visitors reach it.

That is intentional.

The portfolio should never behave like GitHub.

GitHub becomes supporting evidence.

Not the primary experience.

---

# Success

Visitors should never ask

"Where do I start?"

The architecture should quietly answer that question before it is ever asked.
