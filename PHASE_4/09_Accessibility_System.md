# Phase-4-Interaction-Language/09_ACCESSIBILITY_SYSTEM.md

# Accessibility System

Version 1.0

---

# Philosophy

Accessibility is not compliance.

Accessibility is respect.

Every visitor deserves the same understanding,

regardless of ability.

Accessibility should never feel like an additional feature.

It should feel like good design.

---

# Principle 01

Understanding should never depend on

colour,

animation,

audio,

or precision.

---

# Principle 02

Every interaction has a keyboard equivalent.

---

# Principle 03

Every animation has a reduced-motion alternative.

---

# Principle 04

Every interactive element has visible focus.

---

# Principle 05

Typography should remain readable under all conditions.

---

# Colour

Never communicate information through colour alone.

Every coloured element must have

shape,

position,

label,

or icon support.

---

# Motion

Respect

prefers-reduced-motion.

Replace

camera movement,

large transitions,

parallax,

physics

with

opacity,

layout,

crossfade,

scale.

---

# Keyboard

Tab order should follow story order.

Never layout order.

Users should navigate naturally through the experience.

---

# Screen Readers

Use semantic HTML.

ARIA only when necessary.

Hero objects require descriptions.

Architecture diagrams require summaries.

Project screenshots require meaningful alt text.

---

# Focus Behaviour

Focus should never disappear.

It should feel elegant.

Never use default browser blue.

Design custom focus indicators.

---

# Performance

Accessibility must never reduce responsiveness.

Accessibility is part of the product,

not an optional mode.

---

# Success

A visitor using only

keyboard,

screen reader,

or reduced motion

should still understand the same story.
